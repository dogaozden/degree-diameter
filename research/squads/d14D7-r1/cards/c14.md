# c14: polygon cover + extra vertices (beat the table by a few vertices?)
The table graph (GH(11)+2 over Z5) is 14-regular, so no vertex can be added unless some edges are removed while
keeping diameter 7. A new vertex z is within distance 7 of everything if it has at least one neighbour in every copy
(GH ball arguments), but each neighbour needs a free degree slot. Study this at small scale where checking is cheap:
GH(3)+1 over Z3 (2,184 vertices, degree 5, (5,7)) and GH(3)+2 over Z5 (3,640, degree 6, (6,7)). Build the lift
(glift EVAL=1 EDGES=...), find lifted edges whose individual removal keeps diameter 7 (write a fast checker: removing
edge uv only matters for pairs whose short paths use it), then find a SET of removable edges and attach as many new
vertices as possible (each new vertex adjacent to freed slots, at least one neighbour per copy), keeping diameter 7
(verify with apsp). You may choose the matchings (glift with HT = DGQ values, SIGMA free, can optimize a different
objective; or random). Report how many vertices you could add and how that might scale to q = 11, j = 2.
Score: number of extra vertices added at small scale with apsp VALID (unit "extra vertices", say which base).
Compute: at most 6 heavy runs of <= 300 s.
