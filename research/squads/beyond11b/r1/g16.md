# g16: SL(2,p) x H with H a NONABELIAN odd-order group instead of Z_n, odd D cells (7..10, 11)
Idea: at odd D the central elements (2n of them in SL(2,p) x Z_n) are clumped holes, which is why only small n works
and the group-order list is sparse. Replace Z_n by a Frobenius group H of odd order with trivial centre:
H = Z_7 x|_2 Z_3 (order 21), Z_13 x| Z_3 (39), Z_19 x| Z_3 (57), Z_31 x| Z_3 (93), Z_11 x| Z_5 (55), Z_31 x| Z_5 (155)...
Then the centre of G is just {+-I} and there are no new involutions. haar_sym supports it: GROUP = `prod sl p meta m k r`
with n = 1 (check the spec syntax in haar_sym.c), ORBIT "3 m f" (alpha = conjugation by an element of order 3 of G; make
it act on both factors, ALPHA= to override). Example: (8,11) SL(2,103) x H21 has N = 22,945,104 (2N = 45,890,208 >
45,329,808) at mu ~ 13.3. Find more (p, H) just above each cell's value (W(d,11) = 1 + d sum_{i=1..5} (d-1)^(2i-1)).
Scorer: build_haar2.py supports prod/meta (2N <= 2M); haarcheck_gen does NOT support meta - for larger finds report the
file (the director checks). Cap 180 MB. Folder: research/squads/beyond11b/r1/g16/.
